# Стилізація та адаптивна верстка

**Практична робота:** ПР 5 «Стилізація та адаптивна верстка»
**Сторінки:** 6 сторінок у [client/static/](../client/static/) + каталог на Tailwind
[recipes-tailwind.html](../client/static/recipes-tailwind.html).

## 1. Як влаштовано CSS

| Файл | Що в ньому | Звідки |
|---|---|---|
| `client/static/css/reset.css` | Мінімальний reset: `box-sizing`, відступи, `img { max-width: 100% }`, списки з класом без маркерів | ПР 5 |
| `client/styles/tokens.css` | Дизайн-токени: кольори обох тем, відступи, радіуси, тіні, шрифти, шкала `clamp()` | ПР 3 |
| `client/styles/typography.css` | Базова типографіка в `rem` і `clamp()` | ПР 3 |
| `client/styles/components.css` | Кнопки, поля, чипи, бейджі, картка, перемикач порцій, шапка, футер | ПР 3 |
| `client/static/css/site.css` | Розкладка сторінок: шапка, сітки, форми, каталог, рецепт, контакти, 404 | ПР 5 |

**Mobile-first.** Базові правила написано для 360 px; ширші екрани додаються лише
медіазапитами `@media (min-width: 768px)` і `@media (min-width: 1280px)`.

| Елемент | Технологія | 360 px | 768 px | 1280 px |
|---|---|---|---|---|
| Шапка | Flexbox | логотип, «☰ Меню», тема | меню в рядок + «+ Додати рецепт» | те саме, більший логотип |
| Бургер-меню | `<details>` без JS | розгортається по кліку | `<summary>` сховано, меню видно завжди (`::details-content`) | те саме |
| Картки рецептів | Grid `repeat(auto-fill, minmax(min(100%, 16rem), 1fr))` | 1 колонка | 2 колонки | 3 (каталог) / 4 (головна) |
| Каталог | Grid | фільтри згорнуті в `<details>` | те саме | фільтри — бічна колонка 18rem, завжди відкриті, `sticky` |
| Сторінка рецепта | Grid | усе в колонку | фото на всю ширину | інгредієнти — права «липка» колонка |
| Форми | Grid | поля одне під одним | інгредієнт: назва / кількість / одиниця в рядок | ширина форми до 52rem |

**Стани:** `:hover`, `:focus-visible` (рамка 3 px кольору `--color-focus` з відступом 2 px),
`:disabled`, `:user-invalid` (червона рамка помилки лише після взаємодії з полем).
Переходи `transition` 150–250 мс; при `prefers-reduced-motion: reduce` анімації й підйом
карток вимкнено (правило в `components.css`, `scroll-behavior` — у `reset.css`).

**Темна тема.** Значення кольорів перевизначаються в `tokens.css` через
`prefers-color-scheme: dark` і `[data-theme="dark"]`; перемикач ◐ у шапці
([js/theme.js](../client/static/js/theme.js)) зберігає вибір у `localStorage`, підпис кнопки
показує дію («Темна тема» / «Світла тема»). Короткий скрипт у `<head>` застосовує збережену
тему до першого малювання. Повноцінний JS сайту — у ПР 6.

**Орнамент — рівно у 3 місцях:** логотип (inline SVG, щоб текст логотипа брав колір із
токенів), смужка над футером (`ornament-divider.svg` як фон `repeat-x`), петриківка на
404 і в порожньому стані каталогу «Нічого не знайдено» (блок підготовлено з `hidden`,
показуватиме JS у ПР 6).

## 2. Порівняння: чистий CSS і Tailwind CSS

Обидві версії каталогу мають однакову розмітку за змістом і однаковий вигляд у світлій та
темній темах. У Tailwind-версії кольори в `tailwind.config` — це посилання на ті самі
CSS-змінні (`primary: 'var(--color-primary)'`), тому темна тема працює через `tokens.css`
без жодного `dark:`-класу.

Виміряно 14.11.2026 скриптами (рядки — непорожні, gzip — для оцінки передачі мережею;
браузер — Chrome 157, 1280×900, без кешу, сторінки з диска, одне вимірювання — орієнтовно):

| Показник | Чистий CSS (`recipes.html`) | Tailwind (`recipes-tailwind.html`) |
|---|---|---|
| Рядків HTML | 369 | 388 (з них 30 — `tailwind.config`) |
| Розмір HTML | 24,8 КБ (gzip 5,1 КБ) | 41,2 КБ (gzip 6,9 КБ) |
| Класів у розмітці | 143 (49 унікальних) | 1363 (192 унікальних) |
| Символів у атрибутах `class` | 2 020 | 16 602 |
| Власний CSS | 5 файлів, 1 607 рядків, 40,0 КБ (gzip 9,2 КБ) — **на всі 6 сторінок** | 0 рядків (+ `tokens.css` 7,0 КБ) |
| Що ще завантажує браузер | — | скрипт Play CDN: 440,6 КБ (≈127 КБ при передачі), який у браузері генерує ~15,9 тис. символів CSS |
| DOMContentLoaded / FCP | 246 мс / 320 мс | 373 мс / 404 мс |
| Час розробки (з AI-асистентом, за мітками комітів) | ≈ 9 хв на всі 6 сторінок | ≈ 5 хв на 1 сторінку (повторення готового дизайну) |

Час розробки показує роботу з AI-асистентом і не дорівнює часу ручної верстки; головне
тут — співвідношення: Tailwind-версія повторювала вже готовий дизайн, тому була швидшою.

### Плюси і мінуси

| | Чистий CSS | Tailwind CSS |
|---|---|---|
| **Плюси** | Чиста семантична розмітка, мало класів; один `site.css` обслуговує 6 сторінок; менше завантажується; легко читати HTML | Швидко верстати: не треба вигадувати назви класів і перемикатися між файлами; стилі видно прямо в розмітці; обмежена шкала (відступи, розміри) тримає дизайн послідовним; невикористані стилі не потрапляють у збірку |
| **Мінуси** | Треба вигадувати назви класів; CSS росте, складно зрозуміти, чи правило ще потрібне; ризик конфліктів специфічності | Розмітка «роздувається» (у 9,5 раза більше класів); довгі рядки класів важко читати й рев'ювити; конфлікти утиліт (`w-full` + `w-auto`) вирішує порядок у згенерованому CSS, а не порядок у `class`; Play CDN — 440 КБ JS, лише для навчання/прототипу, у продакшені потрібна збірка через CLI |

**Висновок для проєкту:** для статичних сторінок ПР 4–6 лишаємо чистий CSS з токенами.
Під час переходу на React (ПР 7) Tailwind можна розглянути — там розмітка розбита на
маленькі компоненти, і довгі рядки класів не повторюються вручну.

## 3. Перевірка в браузерах

Перевірено автоматизовано через `puppeteer-core` у встановлених браузерах:
**Chrome 157** і **Firefox 160**; кожна сторінка на ширині **360, 768, 1280 px** у
**світлій і темній** темі (7 сторінок × 3 ширини × 2 теми × 2 браузери = 84 знімки).

| Перевірка | Chrome 157 | Firefox 160 |
|---|---|---|
| Горизонтальний скрол (ширина документа > ширини вікна) на всіх 7 сторінках | немає | немає |
| Бургер-меню на 360 px: закрите → клік «☰ Меню» → видно пункти і «+ Додати рецепт» | ✅ | ✅ |
| Меню з `<details>` видно без кліку на 768 і 1280 px (`::details-content`) | ✅ | ✅ |
| Фільтри каталогу відкриті на 1280 px | ✅ | ✅ |
| Темна тема: кольори з токенів, логотип читається | ✅ | ✅ |
| Tailwind-версія виглядає так само, як CSS-версія | ✅ | ✅ |

**Знайдено і виправлено під час перевірки:**
- на 360 px форма «Додати рецепт» виходила за екран на 5 px — grid-колонки `fieldset`
  розтягувалися під мінімальну ширину полів; виправлено `grid-template-columns: minmax(0, 1fr)`;
- на 768 px кнопка «+ Додати рецепт» переносилася на 2 рядки — `white-space: nowrap`
  і менший відступ між пунктами меню;
- нумеровані списки без класу (хлібні крихти, кроки калькулятора) показували і нативні
  номери, і власні кружечки — прибрано маркери.

**Валідність:** HTML усіх 7 сторінок — 0 помилок (W3C Nu Validator). CSS (режим `--css`) —
без помилок, крім двох рядків з `::details-content`: валідатор (версія 24.10) ще не знає цей
псевдоелемент зі специфікації CSS Pseudo-Elements Level 4, хоча обидва браузери його
підтримують. Під час перевірки `components.css` з ПР 3 запис `@media (width >= 768px)`
замінено на `(min-width: 768px)` — для однакового стилю mobile-first у всіх файлах.

**Примітка до знімків:** на повносторінкових скриншотах зображення з `loading="lazy"`
нижче першого екрана можуть бути порожніми — браузер не встигає їх завантажити, бо сторінку
ніхто не прокручує. У звичайному перегляді вони з'являються під час прокрутки.
