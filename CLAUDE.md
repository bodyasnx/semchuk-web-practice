# Інструкції для Claude Code

## Про проєкт
Навчальна практика «WEB-технології та WEB-дизайн». Один веб-проєкт проходить 10 практичних
робіт (ПР 1–10). Тема: «Рецепти української кухні». Основна сутність: рецепт.
Обов'язкова функція: перерахунок інгредієнтів на кількість порцій.
Вимоги, сторінки, структура даних і API описані в `docs/TZ.md`. Це джерело правди.

## Мова
- Інтерфейс сайту, документація в `docs/` і пояснення для мене — українською.
- Код (назви змінних, функцій, компонентів) — англійською.

## Git
- Повідомлення комітів: Conventional Commits з українським описом.
  Приклади: `feat: додано перерахунок порцій`, `fix: виправлено округлення яєць`,
  `docs: додано таблицю ендпоінтів`, `style: ...`, `test: ...`, `refactor: ...`.
- Комітити маленькими змістовними кроками (3–5 комітів на ПР), не одним великим.
- Нову функціональність робити в окремій гілці (`feature/...`, `docs/...`),
  потім Pull Request у `main`.
- Після завершення ПР ставити тег `pr-01` … `pr-10`.
- Перед `git push` показувати мені, що буде відправлено.
- Ніколи не комітити `.env`, `node_modules/`, `dist/`.

## Структура
```
docs/            TZ.md, UX.md, AI.md, API.md, AUDIT.md, report.pdf
client/static/   статичні HTML/CSS/JS-сторінки (ПР 4–6)
client/          React + Vite (ПР 7+)
server/          Express API (ПР 8)
```

## Технічні вимоги
- Mobile-first: 360, 768, 1280 px. Темна тема через `prefers-color-scheme` і `data-theme`.
- Семантичний HTML, рівно один h1 на сторінці, валідний за W3C.
- Доступність: label для всіх полів, alt для зображень, видимий фокус, контраст ≥ 4,5:1.
- Lighthouse (mobile) ≥ 90 у всіх 4 категоріях: зображення WebP з width/height, lazy loading.
- Валідація форм на клієнті і на сервері (400 з переліком помилок, 201 при успіху).
- Телефон у форматі `+380XXXXXXXXX`.
- Зображення: лише власні, вільні (Unsplash/Pexels) або згенеровані; записувати джерела.

## Як зі мною працювати
- Я студент і маю захищати кожну ПР: після кожного етапу коротко поясни,
  що зроблено, які файли змінено і як працює ключовий код.
- Якщо щось я маю зробити сам (браузер, GitHub, акаунти, скриншоти) — дай покрокову
  інструкцію і скажи, що саме заскрінити для звіту.
- Наприкінці кожної ПР нагадай про тег і запис у щоденник практики.
